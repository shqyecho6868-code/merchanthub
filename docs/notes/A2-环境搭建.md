# A2 环境搭建：本项目特有的调整与原因

> 通用的 Docker / Maven 基础不在这里讲，只记录“本项目为什么这么做”。

## 1. 依赖：根 pom 只管版本，Common 的重依赖设为 optional

- **问题**：旧根 pom 把 web、MyBatis、Redis、LangChain4j 等依赖塞给了所有模块。Gateway 是 WebFlux（响应式）应用，却被迫带上了 Servlet 栈，只能靠配置硬压。
- **做法**：
  - 根 pom 只在 `dependencyManagement` 里统一版本；`<dependencies>` 里只留 lombok（编译期）和 starter-test（测试期），这两个不会进入运行时。
  - Common 里 Servlet / MyBatis / AOP 相关的依赖标为 `optional`：Common 自己编译能用，但**不传递**给使用方。
  - Common 中依赖这些库的 Bean 加了条件装配，比如 `@ConditionalOnClass(name = "...")`：classpath 上有对应的类才创建。用**字符串**类名，是为了类不存在时也能安全判断。
- **验证**：`dependency:tree` 确认 Gateway 里不再有 webmvc/tomcat，只有 ai 服务带 LangChain4j，不连数据库的 realtime、ai 不再带 MyBatis-Plus。

## 2. AI 护栏异常从 Common 挪到 ai 服务

- Common 的全局异常处理引用了 LangChain4j 的异常类，导致所有服务都必须依赖 LangChain4j。现在挪到 `AiService/.../exception/AiExceptionHandler.java`。
- 加了 `@Order(HIGHEST_PRECEDENCE)`：护栏异常也是 `RuntimeException`，如果 Common 的处理器先匹配，就会被当成普通异常，返回“系统错误”。

## 3. RocketMQ 的 `brokerIP1 = host.docker.internal`

- **背景**：客户端先问 NameServer“Broker 在哪”，再**直接连**拿到的地址。Broker 默认注册的是容器内网 IP（172.x），Mac 上的程序连不上，表现为发消息超时。
- **为什么不用 127.0.0.1**：Dashboard 也在容器里，它访问 127.0.0.1 访问到的是自己。
- **为什么不用局域网 IP**：你在校园网下，IP 会变（当前是 10.246.x.x），每次换网络都要改配置。
- **方案**：统一用 `host.docker.internal` 这个名字。
  - 容器侧：compose 里配置 `extra_hosts: host-gateway`，把它解析到宿主机，再经端口映射到 Broker。已验证 Dashboard 能读到 Broker 的 57 项运行指标。
  - 宿主机侧：需要在 `/etc/hosts` 加一行（见 `env-setup.md` 第 5 节），等写 RocketMQ 代码前再做。

## 4. RocketMQ 存储卷的权限：加了一个 `broker-init`

- **现象**：Broker 反复重启，日志里只有关闭阶段的 NPE（这是“初始化失败后关闭”时的副作用，不是根因）。
- **根因**：镜像以 uid 3000 运行，新建的命名卷属于 root，写不进去。
- **做法**：加一个一次性服务，以 root 身份 `chown` 存储目录后退出；Broker 通过 `depends_on: service_completed_successfully` 等它完成后再启动。换一台新电脑 clone 下来也不会再遇到这个问题。

## 5. 版本对齐

- SCA 选 `2025.0.0.0`（GitHub wiki 的对照表停在 2023 年，以官方站 sca.aliyun.com 为准）。
- Nacos 服务端选 `v3.0.3`，与 SCA 自带的客户端版本一致；RocketMQ 选 `5.3.1`，与 SCA 推荐版本一致。
- Nacos 3.x 默认开启鉴权，首次使用需要初始化管理员密码（已通过 API 完成，密码在 `.env`）。

## 6. 端口

- Nacos 必须映射 **9848**：2.x 以后客户端注册走 gRPC，端口固定是 8848+1000。只映射 8848 时，控制台能打开，但服务注册会超时。
- Dashboard 2.1.0 在容器内监听 8082（不是 8080），正好避开 Nacos 3.x 控制台的 8080。

## 7. 时区用西雅图时间

- 容器设置 `TZ=America/Los_Angeles`，各服务 jdbc 的 `serverTimezone` 同步修改。
- Java 代码里还有几处写死的 `Asia/Shanghai`，留到写订单代码时统一处理（行业通行做法：数据库存 UTC，展示时按用户时区转换）。
